# First-delivery implementation roadmap

Target first delivery: 2026-10-21. Work starts from `delivery/windows-v0.2.0`; the development branch is separate, and old release packages must remain unchanged.

## Priority A

Audit/rebuild baseline, cite consulted implementations and access limits, define measurable gates, implement regional analysis/uncertainty, separate C(t), connected transitions, discrete attack protection, conservative overlap/minimum-intervention decisions, cancellation and actual rendered-audio tests. Build the real Windows VST3 if the retained cross toolchain works; run its actual factory/audio harness under Wine, with inner Windows exit codes. Save corpus evidence and exact limitations. These tasks define the first engineering delivery; the result is not a commercial quality certification.

## Priority B

Improved robust centres and multiple-window behavior are part of the first implementation. Swap source/target rows according to this brief and expose meaningful adaptive precision/override controls. Reusable reference capture must be separate from instantaneous following, persist uncertainty/variants and survive source silence. If implemented, it requires state, retained-map and no-allocation callback tests; otherwise label it unfinished rather than adding a misleading button. Add licensed real recordings, multi-detector benchmarks and more spectral/decay measures as data becomes available.

## Priority C / next gates

Human blind listening and native latest Sonar/HP validation; global constrained trajectory optimization; calibrated ensemble confidence; better onset/tail inference; piano-specific partial/stretch model; independent polyphonic correction; neural separation/detectors; a validated language-action interpreter and optional authorized secure AI service. No fabricated passes or placeholder UI can substitute for those capabilities.

Publishing a GitHub Release, remote deployment, uploading private audio or buying a dependency is outside this authorization. The requested development branch and reviewable build/test packages are the delivery mechanism. Read actual final logs/report for completed versus incomplete items.
