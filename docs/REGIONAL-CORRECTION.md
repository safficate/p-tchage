# Adaptive regional translation

The source contour `P(t)` and correction `C(t)` are separate. The intended corrected contour is `P(t)+C(t)/100` when pitch is expressed in semitones and C in cents. A smooth or straight correction does not imply a straight source note.

`Frame` stores F0, periodicity confidence, amplitude, cross-window agreement, onset evidence and uncertainty. `Note` adds stable bounds, robust centre uncertainty, discrete-decay hypothesis and overlap risk. Stable local linear trends plus weighted median/Huber refinement estimate centres. Frames with unreliable agreement do not establish an anchor. Compatible stable runs can merge across vibrato excursions, but not across silence or an identified reattack. Distinct occurrences/variants remain separate notes; detached manual targets remain available.

A target is explicit: reference matching uses the chosen destination note/cent map; relative mode adds entered cents to the original event. The engine never invents a makam or switches to equal temperament merely because analysis finished. Legacy states retain legacy semantics.

Each region has requested and effective displacement, uncertainty, confidence, decision/reason, calibration and actual verification values. Decision families are unchanged, constant translation, reduced translation, shared correction and review. Near-zero requests can return original PCM. With minimum intervention enabled, the comparison is `max(user precision, 1.5 * estimated centre uncertainty)` rather than one instrument-independent cent cutoff. Low confidence/large uncertainty yields review. User precision and minimum-intervention controls are never moved automatically.

The first optimizer is deliberately constrained and local rather than a claim of a solved global perceptual model. Its data term favors requested centres with weights proportional to confidence/(1+uncertainty²). Its transition constraint limits correction slope within the observed transition interval. Overlap/confidence rules can dominate centre accuracy. This approximates a weighted least-squares pair projection under a bounded correction difference; it does not estimate psychoacoustic weights from a trained model. The local projections are iterated up to 64 times, preserving hard-zero decisions. Identified overlap chains are a single variable; a later conflict declines the whole chain in both directions. A final feasibility check declines the whole clip if slope constraints have not converged. This is not a proof of a global optimum; a more useful global constrained solver remains future work.

Calibration is bounded, offline and measured only inside stable regions. It adjusts a constant regional trim, not individual vibrato extrema. It must not rescue a fundamentally wrong pitch track by applying a large offset. A declined plan copies source PCM exactly; a nonzero plan uses the existing spectral shifter and must be separately tested for sound quality.

Acceptance tests and corpus outputs are linked from `TEST-PLAN-3.0.md`. No universal musical-naturalness or sub-cent accuracy guarantee follows from stable synthetic-tone metrics.

Stable verification uses eight periodicity observations; exceptionally flat, long events use 16,384-sample windows plus a narrow-band Hann spectral fundamental estimate from up to 1.2 seconds. A bounded constant trim can be refined over at most four render passes. When both methods exist their midpoint drives calibration, and both raw estimates are retained in plan JSON. They need not agree on a spectrally altered signal; the independent acceptance checks must each pass, rather than accepting only the midpoint. This does not implement pYIN or a general FFT-bin pitch tracker.

Shared overlapping groups are not calibrated event by event. Individual calibration would violate their common offset. Calibration is restricted to unconstrained translated regions and scaled back when trims would exceed a planned connected-transition slope bound. Conflicting late members cannot leave an earlier shared member processing alone. The regression suite explicitly checks a three-event chain as well as a two-event conflict.
